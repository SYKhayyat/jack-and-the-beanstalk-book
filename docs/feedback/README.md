# Feedback instruments — what this folder is

The assignment asks for two sets of ten responses and a short comparison
between them. This folder holds the material for the first, wall-clock-sensitive
part: **ten real people**, recruited through a crowd service, each spending
about three minutes on one finished picture book.

| File | What it is | Who uses it |
| --- | --- | --- |
| [engage-survey.md](engage-survey.md) | The survey, written out in full, ready to paste into Engage. One short description for Engage to build from, then the whole instrument: questions, order, what is shown, and the logic that keeps it to three minutes. | Paste into Engage |
| [cloudresearch-setup.md](cloudresearch-setup.md) | Step-by-step Connect setup, plus the fee-waiver email to Touro support, plus the runbook for the study window itself. | The developer |
| [comparison-template.md](comparison-template.md) | The comparison skeleton: real ten versus AI ten, with the "what one caught that the other missed" sections both ways — filled in after the responses land. | The developer |
| [ai-persona-plan.md](ai-persona-plan.md) | The AI-persona harness as a **design only**. No code is written for it in this step, and the method stays unpublished until after Monday's class comparison. | The developer |

Ground rules that hold for everything here:

- Every instrument is written so a participant can answer it without any
  explanation from the developer.
- No instrument asks for, or reveals, anything about how the pictures are made
  beyond the one honest sentence the app itself shows: the pictures are real.
- The comparison is where the two response sets meet. Nothing in it is written
  before both sets exist — the skeleton carries the questions and the shape,
  not the answers.
