# Audit — 2026-11-05

A read-through of the whole app (routes, services, stores, prompts, templates,
front-end modules, tests, deployment files), looking for behavioural defects,
robustness gaps and maintenance debt. Every item below says what it is, where it
lives, and what was done about it.

Severity: **high** = a user-visible path is broken or data can be lost;
**medium** = a real defect on an uncommon path, or a misleading guarantee;
**low** = debt that makes the next change harder.

## Fixed in this pass

### 1. Replacing a non-star character's face could never work — high

`app/static/book-detail.js` posted the new photo to `/api/cartoonify` without
the `character` field. The server therefore made a *star* portrait
(`cast_key == ""`), and `POST /api/book/{id}/edit` correctly refused it with
"that portrait was made for a different character". The UI's "Replace a face"
form was dead for the mother, the old man and the giant; only "the star"
worked. Fixed by sending the chosen slot, and pinned by a front-end structure
test.

### 2. A refused edit rewrote the running book's status — high

`BookRunner.start_edit` published the new "rendering" status before asking
whether an edit was already running for that book. The second request got its
409, but it had already overwritten the live job's poll document: pages that
were `making` became `pending`, and a book in its PDF-assembly phase was put
back into the pages phase. The busy check now happens before any write, with
the job's slot reserved synchronously so two simultaneous requests cannot both
pass it. Pinned by a test that starts an edit, has a second request refused,
and asserts the first job's `making` tile survived.

### 3. Deleting a book left its render running — high

`DELETE /api/book/{id}` (and the `action=delete` edit) deleted the store while
the background render still held a reference to it. The job kept making
billable page calls, then failed writing into the deleted directory, and its
error handler tried to write a status document that had nowhere to go. Delete
now cancels the book's job first; the render's cancellation path refuses to
recreate a book that is gone. Pinned by a test with a slow provider.

### 4. A character edit stored a face before validating it — medium

`edit_book(action="character")` called `save_character` first and only then
checked whether that character appears in the book. A key that is photoable but
absent from this book's pages left a portrait stored under the book and then
returned 422. Validation now comes first.

### 5. Book retention was measured from creation, not completion — medium

Both stores deleted a book once it was older than `BOOK_RETENTION_DAYS`,
counting from `created_at`, while the interface and both docstrings promise
"finished longer ago than the window". A book made on day 1 and edited on day
8 disappeared the moment the sweeper ran. Retention now uses the document's
last update (`updated_at`), so a finished or edited book lives a full window
from its last activity. Pinned in the file and database stores.

### 6. Per-user file writes shared one temporary filename — medium

`FileUserStore.upsert` wrote to `<sub>.json.tmp` and renamed it. Two
simultaneous sign-ins of the same account (a double callback, two tabs) used
the same temporary path: one writer could see the other's half-written file or
fail on the rename. It now uses the same pid+uuid temporary name the book store
already uses, and removes it on every path.

### 7. Download links forced a `.png` name on JPEG artwork — low

The book detail page set `download="…png"` on the portrait and photo links
while the server chooses the extension from the bytes (providers may return
JPEG). The browser therefore saved a JPEG named `.png`. The links now leave the
filename to the server's `Content-Disposition`.

### 8. Media sniffing had five copies — low

`_media_type`/`_detect_media_type`/`_extension_for` were repeated in
`routes/book.py`, `services/storage.py`, `services/book_store.py`,
`services/db_book_store.py` and `services/book_runner.py`. They all answer the
same question ("what are these bytes?") and had already drifted in small ways.
One helper module now owns it.

### 9. The portrait response fabricated a filesystem object — low

`routes/api.py::_cartoon_payload` built `StoredGeneration(Path(), id)` just to
borrow two URL-formatting methods, which made a response serializer pretend to
know about a store root. The URL helpers are now plain functions of the
generation id.

### 10. Coverage artefacts escaped `.gitignore` — low

A `pytest --cov` run interrupted mid-write left `.coverage.*` files that
`.gitignore`'s exact `.coverage` line did not match. The pattern now covers
them.

## Observed and deliberately left alone

These are documented design choices, not defects; changing them would be a
different product decision.

- **Unowned books are readable by any session.** Password/open deployments have
  no identity, so there is nothing to file a book under. Google mode always
  files an owner and returns 404 to anyone else.
- **The rate limiter and the edit registry are per process.** A multi-worker
  deployment would need a shared store. Render runs one process; the docstrings
  say so.
- **The image call in flight cannot be cancelled.** A deleted book's already
  sent HTTP request still returns, because aborting a billable call is not
  something the provider contract supports. Cancellation stops *further* calls;
  it does not retry or abandon one in flight (there are no retry loops).
- **`HANDOFF.md` is history.** It still says payments are out of scope; the
  brief was written before the accounts-and-money iteration. `README.md` and
  `to-do.md` are the current documents.
