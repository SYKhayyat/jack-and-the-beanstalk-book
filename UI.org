* Fix first (severity order)
** TODO Q1 The review loop never runs in production  [answers note 6]
The "quality loop" (tier 1, tier 2, up to 3 tries, best-of-3) is effectively
dead code on the live site.
- =BookRunner._judge= (app/services/book_runner.py:781) returns
  =passed=True, tiers_run=()= when =not artwork.plates=. A book gets plates only
  through its pinned =template_version_id=
  (app/services/template_store.py:697).
- The plate start gate is off (to-do.md: "the start gate stays off until it is
  seen to keep the plate's background"), so *every* book has
  =template_version_id = NULL=.
- Prod DB, read-only: 3 books, all =template_version_id = None=; 56 pages,
  =sum(attempt_count) = 0=, =count(review) = 0=. The cost ledger has no review
  calls at all.
- Result: Agnes' Red book (f944a510…) shipped with pages that are *contact sheets*
  (grids of 12–20 little tiles of characters and rooms, some with numbers
  printed in the corners: pages 1, 6, 13). It was never looked at.
- The wallet and to-do.md say "Every generated image is analysed". That's
  currently untrue for every book anyone can make.
Fix:
- Review every picture whether or not the book has plates. Tier 1 without a plate
  can still catch blank/dark/wrong aspect. Tier 2 doesn't need a plate at all.
- Add tier-2 faults for what's actually going wrong: =collage= / =multiple_panels=
  ("more than one scene, a grid, a character sheet, tiles"). Right now
  =parse_answer= silently drops any fault name it doesn't know, so the model
  can't report it. A collage only fails if the model also gives a low score.
- Tier-1 mechanical check for grids: strong regular vertical/horizontal seams
  (column/row gradient energy at fixed intervals). That's free and would have
  caught all of that book's bad pages.
- Make "was it reviewed" visible to the operator (see Q6), so this can't go
  dark silently again.
- Once it runs: a tier-2 *error* (quota, timeout) currently counts as a pass on
  tier 1 alone. That's fine for availability, but log and count it, and show it
  in the admin view.

** DONE G4 [#A] The reader should feel like a book, not a slideshow
Shipped: every page is one surface (art to its edges, the words on the same
paper in Literata at one size for the whole book, a gold rule and a folio, as
in the PDF); two-page spread on wide, short windows, stacked on phones; sized
to the window by =reader-layout.js=; a drop cap on page 1; typographic quotes
in reader and PDF (=app/services/typography.py=); a peel-and-shadow page turn
(=page-turn.js=), an optional synthesized page sound; full-screen story time
(Esc leaves); tap left third = back; "Read to me" highlights each sentence
and turns the page on (=read-aloud.js=).

Your three specifics, all visible on the live book:
1. *The text isn't on the page.* It's a =<figcaption>= in a white strip under
   the art (=.spread-story=), so the picture and the words read as two
   separate things: a photo with a caption. In a picture book the words are
   *part of the page*. Options that still keep text off faces (the rule in
   to-do.md): a facing text page in a two-page spread; text set on a calm
   region of the art (the plates' top band already exists for the cover title,
   and plates could reserve a text area per page); or the art bleeding to the
   page edges with a parchment panel inset over a quiet corner. The PDF and the
   web reader should share the same layout.
2. *Random whitespace.* The 4:3 art is centred inside a wider frame
   (=.spread-art=), leaving cream bars left and right, then card padding,
   then the white text strip, then the frame's border and shadow. Nothing
   bleeds. Make the page one surface sized to the art's aspect (art full-bleed
   to the page edge), and the page itself sized to the viewport so nothing
   sits under the fold.
3. *Terrible font.* Story text uses =--font= (=ui-sans-serif, system-ui=…), the
   same face as buttons and form labels, at ~18 px. Literata is already loaded
   (headings only). Use a book face for the story (Literata, or a rounder
   children's-book serif like Andika/Atkinson for early readers) at 22–26 px
   with generous leading, a drop cap on page 1, and real typographic quotes
   ('Go straight there' is set with straight ASCII apostrophes today).
- Two-page spreads on wide screens (art left, text right on a cream "paper"
  page in Literata at 20–22 px, a drop cap on page 1). Single page on phones.
- Page-curl or slide-with-shadow turn; swipe on touch (already wired).
- Full-screen "story time" mode: hides the site chrome and fills the screen.
  Arrow keys, tap the edges.
- "Read to me": highlight each sentence as it's spoken.
- The story text today is the UI sans at UI size in a white band. It's the
  book's voice. Give it the book's typeface.

* Performance
** DONE P1 Page images are 1.3–1.4 MB PNGs, revalidated on every view
Shipped: WebP copies at 800/1600 px made on first request and kept
(=picture_variants=, migration 0011), under =?w=…&v=<hash>= URLs that are
=private, max-age=31536000, immutable=; a stale =v= is revalidated. The PNG
stays for the PDF.

- =/book-media/<id>/cover= and =/pages/N= are =image/png= at about 1,300–1,400 KB
  (Agnes) and ~1,950 KB (OpenAI),
  with =Cache-Control: private, max-age=0, must-revalidate=. A 21-page book is
  about 28 MB of PNG, and every page turn makes a round trip (~400–800 ms
  measured).
- Chrome froze twice while I was on the book page (screenshot capture timed out
  for 30 s after a scroll). That's consistent with decoding many large PNGs.
Fix: store/serve JPEG or WebP at display size (≈1200 px wide, ~150 KB). Keep
the PNG only for the PDF if it needs it. The rows already have =image_sha256=,
so serve under a content-hashed URL with =max-age=31536000, immutable=.

** DONE P2 Thumbnails download the full image
Shipped: the drawer and page map use the 240 px variant; the drawer query no longer reads cover blobs.

The "My books" drawer shows each cover at 44 px wide but downloads the full
1152×864 cover (1.3 MB) per book. The progress strip tiles do the same for every
page. Add a =?w=160= thumbnail variant (or a stored thumb).

** DONE P3 Next page isn't preloaded
Shipped: pages ±2 around the current one are switched to eager after each turn.

Hidden spreads are =loading="lazy"=, so the next page only starts downloading
when you turn to it. Preload index±1 (and ±2) after each turn.

** TODO P4 Fonts
Literata ships as two TTFs, 312 KB each, from =/static/fonts/= with
=Cache-Control: no-cache= (the CSS/JS are fingerprinted, the fonts aren't).
Convert to WOFF2 subsets (~30–40 KB each), fingerprint them, and cache
immutable. Preload the bold one; it's the headings.

** TODO P5 Book generation throughput
- Render: =MAX_CONCURRENT_GENERATIONS=2=, =MAX_GENERATIONS_PER_MINUTE=12=. 21
  images at ~20–30 s each on OpenAI ≈ 4–5 minutes, and the per-minute cap alone
  forbids anything under ~2 minutes. The to-do goal is under 60 s.
- The cover is drawn *alone* before the pages start (=await self._render_cover=
  then =gather(pages)=), so for its ~20 s one of the two slots sits idle. Put
  the cover in the same =gather=.
- To hit 60 s: concurrency ≈ 21 (the provider allows it on a paid key), the
  per-minute cap per *book* instead of per client, and the review overlapped
  with the next paint.

** TODO P6 Every book lookup pulls the PDF and photos from the DB
=DbBookStore.load_record= (app/services/db_book_store.py:135) does
=select(BookRow)=, which reads every column: =portrait=, =source_photo=,
=cover= and =pdf= (4.7 MB for the new book). Then it uses only metadata (id,
about, title, settings…). Any route that loads the record pays several MB from
Neon (us-west-2) per request. Book page TTFB measured ~720 ms vs ~200 ms for the
shelf. Select only the needed columns, or mark the =LargeBinary= columns
=deferred()= in =app/db.py=.
